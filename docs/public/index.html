Get your project’s runtimes in place with one project-level config.

rawenv reads common project files, suggests runtimes and services, then records the setup in a project-level config. Manage it all from a small CLI.

Install rawenv ↓ Explore the source ↗

Available for macOS and Linux. Windows has a release binary; setup is manual.

A smaller setup loop

From project files
to a working setup.

Stop re-deriving the same runtime versions every time you switch projects. rawenv gives your setup a home alongside the code.

01

Start with what’s already there

Detects runtimes and services from files such as package.json, composer.json and docker-compose.yml.

02

Keep setup project-scoped

Writes detected choices to rawenv.toml; runtimes live in rawenv’s own store instead of changing global installs.

03

Check before you get to work

Use rawenv status to see whether configured runtimes are installed and review setup warnings.

The first few commands

A repeatable path into a project.

Run these from the project directory. Detection creates a starting point; review the config before installing anything.

  1. 01rawenv init

    Detect runtimes and services, then create rawenv.toml.

  2. 02rawenv add node@22

    Install a runtime version selected for this project.

  3. 03rawenv up

    Activate configured runtimes for the project.

  4. 04rawenv shell

    Open a shell with rawenv’s configured PATH.

Try the current release

Install on macOS or Linux.

The installer downloads the latest release for your OS and CPU architecture into ~/.rawenv/bin.

On Windows? Download the x86_64 ZIP from Releases and follow the manual setup notes in the README. The shell installer does not support Windows.

macOS · Linux curl -fsSL https://rawenv.com/install | sh

Then add ~/.rawenv/bin to your PATH.
